## 프로젝트 소개

**OMC(One More Chance)**는 그래픽카드, 게이밍 기기, 한정판 IT 디바이스 등 높은 수요를 가진 테크 상품을 대상으로 하는 **한정판 드롭·래플 이커머스 플랫폼**입니다.

사용자는 특정 시간에 오픈되는 상품에 대해 **선착순 구매(Drop)** 또는 **추첨 응모(Raffle)** 방식으로 참여할 수 있으며, 플랫폼은 드롭 오픈 순간 발생하는 대규모 트래픽과 치열한 구매 경쟁 상황을 안정적으로 처리하는 것을 목표로 합니다.

### 프로젝트 목표

- 드롭 오픈 시점의 대규모 동시 접속 환경에서도 안정적인 주문 및 재고 처리 시스템 구현
- Redis 기반 재고 관리와 동시성 제어를 통한 초과 판매(Overselling) 방지
- Kafka 기반 이벤트 드리븐 아키텍처를 활용한 주문·결제·알림 비동기 처리
- MSA 구조를 적용하여 서비스 간 책임을 분리하고 장애 격리 및 독립 배포 환경 구축
- JMeter 부하 테스트를 통해 병목 구간을 식별하고 성능 개선 과정을 검증
- Prometheus, Grafana 기반 모니터링 환경을 구축하여 서비스 상태를 실시간으로 관찰하고 운영 경험 확보

## 서비스 목록

| 서비스 | 설명 |
|---|---|
| **user-service** | 회원가입, 로그인, JWT 인증, 권한 관리 |
| **product-service** | 상품 정보 관리, 재고(Inventory) 관리 (MVP에서 단일 서비스) |
| **drop-service** | 선착순 판매 이벤트 관리, Redis 재고 선점, 드롭 스케줄링 |
| **raffle-service** | 추첨 응모 이벤트 관리, 중복 응모 방지, 추첨 실행 |
| **order-service** | 주문 생성 및 상태 관리, SAGA 오케스트레이션, Outbox 패턴 |
| **payment-service** | 결제 요청/PG 연동, 환불 처리, SAGA 참여 |
| **coupon-service** | 선착순 쿠폰 발급, 할인 계산, 쿠폰 복구/소멸 처리 |
| **notification-service** | Kafka Consumer 기반 비동기 알림 (드롭 오픈, 당첨/낙첨, 주문 완료 등) |

> **인프라 서비스**: API Gateway, Eureka (서비스 디스커버리), Config Server

## 도메인 정의

| 도메인 | 설명 | 비고 |
|---|---|---|
| User | 회원가입, 로그인, 회원 정보 관리 | CUSTOMER / ADMIN 권한 관리 |
| Product | 한정판 상품 정보 관리 | 상품명, 가격, 이미지, 상태 관리 |
| Inventory | 상품 재고 관리 | 선점·확정 차감·복구 처리 |
| Drop | 선착순 판매 이벤트 관리 | 특정 시간 오픈, 한정 수량 판매 |
| Raffle | 추첨 응모 이벤트 관리 | 응모 후 추첨 방식 구매 기회 제공 |
| Order | 주문 생성 및 상태 관리 | 주문·취소·환불 처리 |
| Payment | 결제 정보 관리 | PG 연동 및 결제 상태 관리 |
| Coupon | 쿠폰 발급 및 사용 관리 | 선착순 발급, 할인 정책 관리 |
| Notification | 사용자 알림 관리 | 드롭 오픈, 당첨 결과, 주문 상태 알림 |
| Processed Event | Kafka 이벤트 중복 처리 방지 | event_id 기반 멱등성 보장 |
| Outbox Event | 이벤트 발행 보장 | Kafka 발행 실패 복구용 |
| Failed Event Log | 이벤트 처리 실패 기록 | 운영자 수동 복구 지원 |

## 인프라 개요

```
[Client]
    ↓
[API Gateway :8080]  ← JWT 검증, X-User-* 헤더 주입
    │                   Swagger UI: http://localhost:8080/swagger-ui.html
    ↓
[Eureka :8761]       ← 서비스 디스커버리 (lb:// 라우팅)
    ↓
[각 마이크로서비스]
    ├── PostgreSQL (서비스별 독립 DB/스키마)
    ├── Redis      (재고 선점, 중복 방지, 분산 락)
    └── Kafka      (이벤트 드리븐 비동기 처리)

[Config Server :8888] ← 각 서비스 YAML 설정 중앙 관리 (Native 방식, MVP)
[Zipkin]              ← 분산 추적
[Prometheus + Grafana] ← 모니터링
```

### 주요 아키텍처 결정사항

- **Product + Inventory 통합 (MVP)**: 11일 MVP 일정상 단일 서비스로 운영, 트러블슈팅 기간에 분리 예정. 분리 시 FeignClient 교체만으로 가능하도록 `InventoryPort` 인터페이스로 추상화
- **Config Server Native 방식**: MVP 단계에서는 멀티모듈 내부에 YAML 포함. 운영 규모 확장 시 외부 Git 레포지토리로 분리 가능
- **식별자 UUID v7**: MSA 환경에서 서비스 간 ID 충돌 방지 + IDOR 공격 방어 + B-tree 인덱스 효율(순차 삽입) 모두 확보
