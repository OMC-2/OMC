## 공통

### PostgreSQL 버전 및 UUID v7

```
PostgreSQL 18 이상 → UUID v7 기본 내장 (확장 설치 불필요)
```

| | UUID v4 | UUID v7 |
|---|---|---|
| 생성 방식 | 완전 랜덤 | 시간 기반 + 랜덤 |
| 정렬 | 불가 | 생성 순서대로 정렬 가능 |
| 인덱스 성능 | 랜덤 삽입으로 인덱스 단편화 | 순차 삽입으로 인덱스 효율적 |
| 분산 환경 | 충돌 가능성 낮지만 정렬 불가 | 충돌 없음 + 시간 정보 포함 |

```yaml
# docker-compose.yml
user-db:
  image: postgres:18-alpine
```

### 공통 Audit 필드 (BaseEntity)

수정/삭제가 필요한 모든 테이블에 포함 — BaseEntity 상속

| 필드 이름 | 데이터 타입    | 설명 |
|---|-----------|---|
| `created_at` | TIMESTAMP | 레코드 생성 시간, NOT NULL |
| `created_by` | UUID      | 레코드 생성자 (userId) |
| `updated_at` | TIMESTAMP | 레코드 수정 시간 |
| `updated_by` | UUID      | 레코드 수정자 (userId) |
| `deleted_at` | TIMESTAMP | 레코드 삭제 시간 (Soft Delete) |
| `deleted_by` | UUID      | 레코드 삭제자 (userId) |

> 수정/삭제가 필요하지 않은 테이블은 BaseEntity를 상속하지 않고 필요한 필드만 직접 추가

| event_type | VARCHAR(100) | NOT NULL | | | STOCK_DEDUCTED / STOCK_FAILED |

| 컬럼명 | 타입 | 제약조건 | 설명 |
|---|---|---|---|
| drop_id | UUID | PK, DEFAULT gen_random_uuid() | 드롭 고유 ID |
| product_id | UUID | NOT NULL | 상품 ID (논리 참조) |

| start_at | TIMESTAMPTZ | NOT NULL | 드롭 시작 일시 |
| end_at | TIMESTAMPTZ | NOT NULL | 드롭 종료 일시 |
| total_qty | INT | NOT NULL | 총 재고 수량 |
| hold_ttl_sec | INT | NOT NULL, DEFAULT 600 | 선점 유지 시간 (초, 기본 10분) |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | 생성 일시 |
| created_by | UUID | NOT NULL | 생성자 ID (관리자 userId) |
| updated_at | TIMESTAMPTZ | | 수정 일시 |
| updated_by | UUID | | 수정자 ID |
| deleted_at | TIMESTAMPTZ | | 소프트딜리트 일시 |
| deleted_by | UUID | | 소프트딜리트 처리자 ID |

```sql
CHECK: status IN ('SCHEDULED', 'OPEN', 'CLOSED'), total_qty > 0, end_at > start_at
INDEX (status, start_at)  -- 스케줄러 오픈 대상 조회
INDEX (status, end_at)    -- 스케줄러 마감 대상 조회
```

> INSTANT(선착순) 전용 테이블. RAFFLE는 raffle-service의 p_raffles 테이블이 소유.
> hold_ttl_sec은 드롭마다 다르게 설정 가능 (기본값 600초)
> BaseEntity 상속. `@SQLRestriction("deleted_at IS NULL")` 적용으로 JPA 쿼리에서 소프트딜리트된 드롭 자동 제외.
> created_by / updated_by / deleted_by 는 username이 아닌 userId(UUID)를 저장한다 (V3 마이그레이션 적용).

| aggregate_id | UUID | NOT NULL | orderId (논리 참조) |
| event_type | VARCHAR(100) | NOT NULL | `PURCHASE_CONFIRMED` |
| topic | VARCHAR(100) | NOT NULL | `purchase.confirmed` |
| payload | TEXT | NOT NULL | Kafka 전송 JSON (eventId, orderId, dropId, userId, productId, holdExpiresAt) |

> `FOR UPDATE SKIP LOCKED` native query로 다중 인스턴스 중복 발행 방지.
> MAX_RETRY(5) 초과 시 FAILED 격리 — 수동 확인 필요.

### Redis 키 구조 (드롭)

| 키 | 타입 | 설명 | 생성 | 소멸 |
|---|---|---|---|---|
| `stock:{dropId}` | String | 남은 수량 카운터 | 드롭 오픈 시 SETNX | 정산 후 DEL |
| `purchased:{dropId}` | Set | 1인1구매 차단 (userId) | Lua SADD | 정산 후 DEL |
| `holds:{dropId}` | ZSet | orderId → 만료 epoch | Lua ZADD | 결제/만료 시 ZREM |
| `queue:{dropId}` | String | 접수 순번 카운터 | Lua INCR | 정산 후 DEL |
| `drop:{dropId}:status` | String | OPEN 플래그 (fail-fast) | 드롭 오픈 시 SETNX | 드롭 종료 시 즉시 DEL |
| `hold_ttl:{dropId}` | String | 선점 유지 시간(초) 캐시 — 진입 경로 DB 무접촉 유지 | 드롭 오픈 시 SETNX | 정산 후 DEL |
| `product_id:{dropId}` | String | productId 캐시 — purchase.confirmed 이벤트 조립용 | 드롭 오픈 시 SETNX | 정산 후 DEL |
| `sold_out:{dropId}` | String | 품절 플래그 — Gateway 조기 차단용 | purchase.lua에서 재고 0 도달 시 SET | hold 만료·복구·정산 시 DEL |

> 선점 주체는 drop-service. product-service는 스냅샷 조회 API만 제공.
> holds:{dropId}: ZSet에 만료 epoch를 score로 저장. ZRANGEBYSCORE로 만료 건 조회, ZREM 반환값(1=내가 먼저, 0=상대가 먼저)으로 판정.

## 서비스 간 관계 요약

| 관계 | 카디널리티 | 설명 |
|---|---|---|
| Products ↔ Inventory | 1:1 | 상품 한 개가 한 개의 재고 소유 |
| ORDERS ↔ OUTBOX_EVENTS | 1:N (비식별) | 하나의 주문에 여러 아웃박스 이벤트 발생 |
| ORDERS ↔ FAILED_EVENT_LOGS | 1:N (비식별) | 하나의 주문 처리 중 다수의 에러 로그 누적 가능 |
| ORDERS ↔ Users (User Service) | N:1 (논리 참조) | 한 유저가 여러 주문, user_id로 논리 연결 |
| ORDERS ↔ Products (Product Service) | N:1 (논리 참조) | 단일 상품에 대해 여러 주문 (product_id 논리 참조) |
| ORDERS ↔ Drops/Raffles | N:1 (논리 참조) | 하나의 드롭/래플 이벤트에서 대량의 주문 파생 |
| ORDERS ↔ Coupons | 1:1 (논리 참조) | 1주문 1쿠폰 원칙, applied_coupon_id 참조 (Nullable) |
