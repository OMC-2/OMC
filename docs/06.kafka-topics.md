# 06. Kafka 토픽 명세

> Kafka 이벤트 설계 참고, Consumer/Producer 구현 시 토픽명 확인, SAGA 흐름 추적 시 참조

---

## 토픽명 규칙

```
{도메인}.{동작}
예) drop.opened, payment.completed, stock.failed
```

---

## drop-service 발행

| 토픽명 | payload | 구독 서비스 | 트리거 |
|---|---|---|---|
| `drop.opened` | eventId, dropId, startAt, endAt, totalQty | notification-service | SCHEDULED → OPEN |
| `drop.closed` | eventId, dropId | — | OPEN → CLOSED |
| `purchase.confirmed` | eventId, orderId, dropId, userId, productId, holdExpiresAt | order-service | 선점 성공 |
| `hold.expired` | eventId, orderId, dropId, userId | order-service, coupon-service | TTL 만료 (미결제 — coupon은 RESERVED 있으면 복구, 보통 no-op) |
| `refund.requested` | eventId, orderId, userId, reason | payment-service | ZREM=0 (만료 후 결제, LATE_PAYMENT) |

---

## payment-service 발행

| 토픽명 | payload | 구독 서비스 | 트리거 |
|---|---|---|---|
| `payment.completed` | eventId, orderId, userId, couponId, originalAmount, discountAmount, finalAmount | drop-service, product-service, order-service, coupon-service | 결제 완료 (coupon: RESERVED→USED) |
| `payment.failed` | eventId, orderId, userId, failureReason | drop-service, order-service, coupon-service | 결제 실패 (coupon: RESERVED→AVAILABLE, orderId로 추적) |
| `refund.done` | eventId, orderId, userId, amount, refundReason | coupon-service, notification-service | 환불 완료 — coupon-service가 refundReason=STOCK_DEDUCT_FAILED일 때만 USED→AVAILABLE 복구 |

> `refund.done`의 refundReason: STOCK_DEDUCT_FAILED / USER_CANCEL / RAFFLE_LOSE

---

## product-service 발행

| 토픽명 | payload | 구독 서비스 | 트리거 | 참고 |
|---|---|---|---|---|
| `stock.deducted` | eventId, orderId, productId | order-service | DB 재고 확정 차감 완료 | INSTANT 전용 (PAID→CONFIRMED). 래플은 미발행 |
| `stock.failed` | eventId, orderId, productId | drop-service, payment-service, order-service | DB 재고 차감 실패 | drop: Redis 복구 / payment: 자동 환불 → refund.done / order: CANCELLED |

---

## order-service 발행

| 토픽명 | payload | 구독 서비스 | 트리거 |
|---|---|---|---|
| `order.created` | eventId, orderId, userId, dropId | — | 주문 생성 (INSTANT 전용) |
| `order.confirmed` | eventId, orderId, userId | notification-service | 주문 확정 |
| `order.cancelled` | eventId, orderId, userId, reason | notification-service | 주문 취소 |
| `order.shipped` | eventId, orderId, userId | notification-service | 배송 시작 (배송 스케줄러 SHIPPING 전이) |
| `refund.requested` | eventId, orderId, userId, reason | payment-service | 사용자 환불 요청 (CONFIRMED 상태) |

> `refund.requested`는 두 주체가 발행:
> ① drop-service — 만료 후 결제(LATE_PAYMENT) 자동 환불
> ② order-service — 사용자 직접 환불

---

## raffle-service 발행

| 토픽명 | payload | 구독 서비스 | 트리거 |
|---|---|---|---|
| `raffle.winner.selected` | eventId, entryId, raffleId, userId, productId, paymentId, couponId, originalAmount, discountAmount, finalAmount | order-service, product-service, notification-service | 추첨 당첨 |
| `raffle.loser.notified` | eventId, entryId, raffleId, userId | payment-service, notification-service | 추첨 낙첨 |

> 래플 이벤트는 `dropId`를 싣지 않고 `raffleId`를 사용 (drop·raffle 완전 독립)

---

## coupon-service 발행

| 토픽명 | payload | 구독 서비스 | 트리거 |
|---|---|---|---|
| `coupon.issued` | eventId, couponId, userId | notification-service | 쿠폰 발급 |
| `coupon.used` | eventId, couponId, userId, orderId, entryId, usageType | — (추후 통계용) | 쿠폰 사용 (usageType: DROP / RAFFLE) |

---

## notification-service 발행

없음 — Consumer만

## 전체 이벤트 흐름 요약

```
이벤트                      발행 서비스        → 구독 서비스
──────────────────────────────────────────────────────────────
drop.opened                drop              → notification
drop.closed                drop              → (없음)
purchase.confirmed         drop              → order
hold.expired               drop              → order, coupon
payment.completed          payment           → drop, product, order, coupon
payment.failed             payment           → drop, coupon, order
stock.deducted             product           → order
stock.failed               product           → drop, payment, order
order.created              order             → (없음)
order.confirmed            order             → notification
order.cancelled            order             → notification
order.shipped              order             → notification
coupon.restored            order             → coupon, notification
refund.requested           drop / order      → payment
refund.done                payment           → coupon, notification
raffle.winner.selected     raffle            → order, product, notification
raffle.loser.notified      raffle            → payment, notification
coupon.issued              coupon            → notification
coupon.used                coupon            → (없음, 통계용)
```

## DLQ (Dead Letter Queue)

재처리 불가 이벤트는 별도 토픽(`{원본토픽}.dlq`)으로 분리하여 운영자가 수동 처리한다.

- `p_failed_event_logs` 테이블에 실패 기록 → 운영자 수동 복구
- `UNRESOLVED` 상태로 기록 → 복구 완료 시 `RESOLVED` 변경
- 실패 로그에는 원본 payload 전체가 저장되어 재처리 가능
