# 10. 모니터링 가이드

> Prometheus / Grafana / Zipkin 구성 및 사용법. 로컬 환경 기준.

---

## 모니터링 스택 구성

```
[각 서비스]
  │  /actuator/prometheus  ← 메트릭 노출
  ▼
[Prometheus]  ← 15초마다 메트릭 수집
  │
  ▼
[Grafana]     ← 대시보드 시각화 (Prometheus 데이터 소스)

[각 서비스]
  │  HTTP 요청/응답 시 자동으로 스팬 전송
  ▼
[Zipkin]      ← 분산 트레이싱 수집 및 시각화
```

## Zipkin

### 트레이스 조회 방법

1. http://localhost:19411 접속
2. 상단 검색 필터에서 `+` 버튼 클릭
3. `serviceName` 선택 → `gateway` 입력
4. **Run Query** 클릭

> Zipkin 3.x부터 서비스 드롭다운이 제거됨. 필터 방식으로 조회해야 한다.

### 트레이스 읽는 법

검색 결과에서 각 행이 **요청 1건**이다.

```
Root gateway: post /api/v1/coupons/xxx/issue   11 spans   200ms
```

- **Root 이름** → 게이트웨이가 받은 HTTP 메서드 + 실제 경로
- **spans** → 이 요청에서 생성된 전체 스팬 수 (게이트웨이 + 다운스트림 서비스 합산)
- 클릭하면 워터폴 형태로 각 서비스 간 호출 흐름 확인 가능

### 트레이스 검색 예시

쿠폰 발급 요청만 보고 싶을 때:
1. `+` → `http.url` → `/api/v1/coupons` 입력 후 Run Query

특정 서비스 전체 요청:
1. `+` → `serviceName` → `coupon-service`

## Gateway 포트 구조

게이트웨이는 하나의 프로세스지만 **포트를 2개** 사용한다.

```
게이트웨이 컨테이너
├── 포트 8080  ← API 서버 (클라이언트 요청 처리, Zipkin 트레이싱 됨)
│   └── /api/v1/**
│
└── 포트 8081  ← Management 서버 (운영 도구 전용, Zipkin 트레이싱 안 됨)
    └── /actuator/health   ← Docker healthcheck
    └── /actuator/prometheus  ← Prometheus scraping
```

`management.server.port: 8081`로 Spring Boot의 management server를 분리했다.

**이유**: actuator 엔드포인트(`/actuator/health`, `/actuator/prometheus`)가 초당 수회씩 호출되면 Zipkin에 노이즈가 쌓인다. Management server를 별도 포트로 분리하고 해당 포트의 HTTP 관측을 `ObservationPredicate`로 차단하면 actuator 트레이스가 Zipkin에 기록되지 않는다.

> 다른 서비스(user-service, coupon-service 등)는 포트 분리를 하지 않아서 actuator 트레이스가 Zipkin에 보일 수 있다. 게이트웨이가 모든 요청의 진입점이라 노이즈가 특히 심해서 게이트웨이만 적용했다.

## 샘플링 설정

모든 서비스 `application.yml`:

```yaml
management:
  tracing:
    sampling:
      probability: 1.0   # 100% 샘플링 (개발/스테이징용)
```

운영 환경에서는 `0.1` (10%) 정도로 낮추는 것을 권장한다.

## 트레이스가 안 보일 때 체크리스트

1. Zipkin 컨테이너가 실행 중인지 확인
   ```bash
   docker ps | grep zipkin
   ```

2. 서비스가 Zipkin으로 스팬을 전송하는지 확인 (로그)
   ```bash
   docker logs omc-gateway | grep -i zipkin
   ```

3. Zipkin API로 직접 조회
   ```bash
   curl "http://localhost:19411/api/v2/traces?serviceName=gateway&limit=3" | jq .
   ```

4. `management.tracing.sampling.probability`가 `0`으로 설정되어 있지 않은지 확인
