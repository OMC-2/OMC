# 09. 배포 가이드

> EC2 배포 전체 절차. 최초 세팅 시 또는 인프라를 새로 구성할 때 참조.

---

## 전체 흐름

```
[GitHub Actions]
  1. ./gradlew build -x test  ← JAR 빌드
  2. docker build              ← JAR → Docker 이미지
  3. docker push               → ghcr.io에 업로드
                                       │
                              [ghcr.io]
                              ghcr.io/{org}/omc-user-service:latest
                              ghcr.io/{org}/omc-gateway:latest
                              ...
                                       │
                               docker pull ↓
                              [AWS EC2]
                    4. docker compose up  ← 이미지 받아서 실행
```

---

## 다른 프로젝트에 적용할 때 주의사항

`ghcr.io` 이미지 주소에 GitHub 계정/org명이 포함되어 있어서, **레포 소유자가 다르면 반드시 변경해야 한다.**

| 파일 | 방식 |
|------|------|
| `.github/workflows/cd.yml` | `${{ github.repository_owner }}`로 자동 처리됨 (변경 불필요) |
| `docker-compose.prod.yml` | `${GITHUB_OWNER}` 변수 사용 → `.env.prod`에 값 지정 필요 |

`.env.prod`에 다음을 추가:
```
GITHUB_OWNER=실제-github-org명
```

## 사전 준비물

- [ ] AWS 계정
- [ ] AWS CLI 설치 (`brew install awscli`)
- [ ] Terraform 설치 (`brew install terraform`)
- [ ] AWS IAM 사용자 + 액세스 키 (EC2, 보안그룹 권한 필요)
- [ ] EC2 키페어 `.pem` 파일 (SSH 접속용)

---

## Phase 1 — Terraform으로 EC2 띄우기

```bash
cd infra/terraform
terraform init
terraform plan
terraform apply
```

1. AWS IAM에서 Terraform용 액세스 키 발급
2. `infra/terraform/terraform.tfvars`에 변수 값 입력
3. `terraform init && terraform apply` 실행
4. 완료 후 출력되는 **Elastic IP** 확인 → GitHub Secrets `EC2_HOST`에 등록

> EC2 재시작 시에도 Elastic IP는 유지된다. EC2를 끄고 IP만 남겨두면 과금되므로 주의.

---

## Phase 2 — docker-compose.prod.yml 작성

로컬용 compose와의 차이:

| 항목 | 로컬 | 프로덕션 |
|------|------|---------|
| 이미지 | `build: context: ./services/...` | `ghcr.io`에서 pull |
| 환경변수 | 하드코딩 | `.env.prod` 파일 |
| 내부 포트 노출 | `5432:5432` 등 호스트 바인딩 | 제거 (내부 네트워크만) |
| kafka-ui | 포함 | 제거 |

`.env.prod`는 `.gitignore`에 반드시 추가.

## Phase 3 — GitHub Actions 워크플로 작성

### GitHub 레포 설정 (1회)

GitHub 레포 → Settings → Actions → General → **Workflow permissions**  
→ **"Read and write permissions"** 선택 후 저장

> 기본값이 Read only이면 ghcr.io 이미지 push가 실패한다.

### GitHub Secrets 등록

GitHub 레포 → Settings → Secrets and variables → Actions → **New repository secret**

| Secret 키 | 값 |
|-----------|-----|
| `EC2_HOST` | Elastic IP (`terraform apply` 출력값) |
| `EC2_USER` | `ubuntu` |
| `EC2_SSH_KEY` | `.pem` 파일 내용 전체 (`cat infra/terraform/omc-key.pem`) |

> `GITHUB_TOKEN`은 GitHub이 자동으로 제공하므로 등록 불필요.  
> `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`는 Terraform을 CI에서 실행할 경우에만 필요. 로컬에서 `terraform apply`하는 경우 등록 불필요.

### 브랜치 전략

| 이벤트 | 수행 작업 |
|--------|-----------|
| feature → main PR open/push | CI: 빌드 + 테스트 |
| feature → main PR 머지 | CD: 이미지 빌드 → ghcr.io push → EC2 배포 |

```
[feature 브랜치]
    │  PR open → CI 실행
    ▼
[main]  PR 머지 → CD 실행 (이미지 빌드 + push + EC2 배포)
```

### CD 워크플로 흐름 (`cd.yml`)

```yaml
- name: Deploy to EC2
  uses: appleboy/ssh-action@v1
  with:
    host: ${{ secrets.EC2_HOST }}
    username: ${{ secrets.EC2_USER }}
    key: ${{ secrets.EC2_SSH_KEY }}
    script: |
      cd ~/omc
      docker compose -f docker-compose.prod.yml --env-file .env.prod pull
      docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
```

## Phase 4 — EC2 초기 환경 세팅 (최초 1회)

EC2에 필요한 파일들을 올려두는 작업. **한 번만 실행.**

```bash
./scripts/init-ec2.sh
```

스크립트가 하는 일:
1. EC2에 `~/omc` 디렉토리 생성
2. `docker-compose.prod.yml` 전송
3. `.env.prod` 전송 (`.env`로도 복사)
4. `docker/` 설정 디렉토리 전송 (Keycloak, Postgres 초기화 스크립트)

> `docker compose up`은 실행하지 않는다. 이미지가 아직 없어서 실패하기 때문.  
> 이 스크립트 실행 후 feature → main 머지 → CD 파이프라인이 첫 배포를 처리한다.

---

## Phase 5 — 첫 배포 및 확인

1. feature 브랜치 → main PR 머지
2. GitHub Actions CD 파이프라인 자동 실행:
   - 이미지 빌드 → ghcr.io push
   - EC2 SSH 접속 → `docker compose pull` → `docker compose up -d`
3. 배포 완료 후 헬스체크:

```bash
curl http://<EC2_HOST>:8080/actuator/health
```

이후부터는 **feature → main PR 머지 시 자동 배포**.

## 인프라 삭제

```bash
cd infra/terraform
terraform destroy
```

> EC2와 Elastic IP가 함께 삭제된다. Elastic IP만 남기면 과금되므로 반드시 `terraform destroy`로 정리.
